# Точки роста и триггеры

Живой список «что улучшать и когда пора». Проверять в начале каждой рабочей
сессии над платформой; выполненное переносить вниз с датой.

## Отслеживать

| Точка | Триггер «пора» | Что делать |
|---|---|---|
| **Квота ключа Jina** | Остаток на jina.ai < 1 млн токенов, или в чатах снова 402 | Новый бесплатный ключ на jina.ai либо платный пакет; вставить в Настройки → Инструменты |
| **Русскоязычная выдача поиска** | Заметно слабые результаты по ру-запросам (Авито, локальные цены, ниши) | Изучить параметры локализации Jina Search (страна/язык); если мало — ждать сервера и Serper |
| **Квота Serper (воркер ai-platform-sync)** | В ответах `/search` начали появляться 429/402, либо счётчик на serper.dev приближается к 2500 запросам/мес | Сервер и синк уже развёрнуты — ничего собирать не надо; при исчерпании квоты взять платный тариф serper.dev или просто оставить как есть — web_search сам тихо фолбэчится на Jina |
| **Тарбол SheetJS с CDN вендора** | Сборка падает на шаге `npm ci` с ошибкой загрузки `cdn.sheetjs.com`, либо вендор публикует версию новее 0.20.3 | Проверить доступность CDN; при затяжной недоступности — временно вернуть `xlsx@0.18.5` из npm (уязвимость prototype pollution + ReDoS, только на разбор ЧУЖИХ .xlsx) либо отказаться от Excel-вложений до восстановления |
| **Политика Jina** | Ошибки 401/429 при живом ключе, изменение цен | Перечитать доки Jina, при необходимости сменить поискового провайдера |
| **Агрегаторы с поиском** | Влад подключает Polza/VseGPT/BotHub | Проверить, есть ли у агрегатора режим «:online»/встроенный поиск — может быть качественнее Jina без нашего кода |

## Бэклог (по команде Влада)

- **Автосжатие длинного контекста.** Сейчас `toContext` просто выбрасывает всё,
  что вылезло за `historyLimit` (по умолчанию 20 сообщений). Для BYOK это прямые
  деньги: длинный диалог либо теряет начало, либо оплачивается целиком каждый
  раз. Аккуратный путь — отдельная async-функция рядом с `toContext` (сама она
  синхронная и вызывается в `useMemo`, внутрь неё сетевой вызов не поставить),
  резюме в новом поле `Chat.summary` + `summaryUpToMessageId` (синкается
  бесплатно, миграции Dexie не требует), сжатие через `requestChat`. Не начато
  сознательно: это платный фоновый запрос, его поведение Владу нужно увидеть
  вживую до того, как он станет автоматическим.
- **Голосовой ввод в композере.** В проекте нет ничего (`SpeechRecognition`,
  `MediaRecorder` — пусто). Место под кнопку — ряд контролов капсулы; вставка
  через `setDraftAndResize` (он затирает черновик целиком, для диктовки по
  кускам нужен свой аккумулятор). Веб-распознавание в Safari качеством на
  русском непредсказуемо, серверного аудио-эндпоинта в `client.ts` нет.
- **Перенос данных между пространствами при смене фразы синхронизации.**
  Отложено осознанно: воркер ещё не задеплоен (см. SYNC-SETUP), а писать
  миграцию по крипто-контуру вслепую — худший способ её отладить. До тех пор
  штатный путь переноса — экспорт/импорт из настроек.


- LifeHearth: откатить раздел ИИ (коммит f7c78c4 за флагом) — ждёт подтверждения.
- LifeHearth: гонка критической секции в `src/lib/sync.ts` (runSync: `running = true` после await-разрыва) — тот же дефект, что ревью нашло и починило здесь в engine.ts; чинить отдельным заходом в life-hub со своими проверками.
- GigaChat — только через агрегатор (напрямую из браузера не выйдет: OAuth на :9443 и закрытый CORS).
- Жёсткая привязка фразы синхронизации: смена фразы = новое пространство, старые данные на сервере остаются лежать мусором (space_id больше никем не читается). При необходимости — добавить перенос данных между пространствами или ручную чистку старых.

# Настройка синхронизации и серверного веб-поиска

Разовая инфраструктурная настройка на стороне Влада. После неё всё остальное
происходит само: воркер передеплоивается при каждом пуше в `server/`,
включение синхронизации в приложении — это уже просто «Настройки → ввести
фразу → Включить» на каждом устройстве.

**Аккаунт Cloudflare заводить не нужно** — у Влада уже есть рабочий аккаунт
`xabos161rus` с воркером `life-hub-push` (использован для LifeHearth). Новый
воркер `ai-platform-sync` живёт в том же аккаунте, ничего дополнительно
регистрировать не надо.

## Что это даёт

- **Синхронизация Мак ↔ айфон**: чаты, провайдеры, роли и сниппеты
  обмениваются между устройствами через свой сервер. Сквозное шифрование —
  сервер видит только шифротекст, ни фраза, ни содержимое чатов на него не
  попадают в открытом виде.
- **Веб-поиск через Serper** вместо Jina — обычная google-выдача, обычно
  качественнее по русскоязычным запросам. Это опционально: без ключа Serper
  синхронизация работает полностью, а инструмент `web_search` как раньше тихо
  ходит через Jina — это рабочее состояние, а не ошибка.

## Шаг 1. Токен Cloudflare и Account ID

1. dash.cloudflare.com → иконка профиля (правый верхний угол) → **My Profile**
   → вкладка **API Tokens**.
2. **Create Token** → найти шаблон **Edit Cloudflare Workers** → **Continue to
   summary** → **Create Token**.
3. Скопировать токен сразу — он показывается один раз; если страницу закрыть
   не скопировав, придётся создавать новый.
4. Account ID: главная страница дашборда → раздел **Workers & Pages** → в
   правой колонке блок **Account details** → скопировать **Account ID**.

## Шаг 2. Секреты в GitHub

1. github.com → репозиторий **ai-platform** → **Settings** → **Secrets and
   variables** → **Actions**.
2. **New repository secret** — создать два секрета:
   - `CLOUDFLARE_API_TOKEN` — токен из шага 1.
   - `CLOUDFLARE_ACCOUNT_ID` — Account ID из шага 1.

## Шаг 3. Ключ Serper (необязательно)

Можно пропустить этот шаг — синхронизация от него не зависит, а `web_search`
без ключа Serper продолжит работать через Jina, как сейчас.

1. serper.dev → **Sign up** (бесплатно, 2500 запросов в месяц).
2. **Dashboard** → скопировать **API Key**.
3. Положить его **секретом воркера** (не GitHub-секретом — это разные вещи!),
   любым из двух способов:
   - CF Dashboard → **Workers & Pages** → воркер `ai-platform-sync` →
     **Settings** → **Variables and Secrets** → **Add** → тип **Secret**, имя
     `SERPER_KEY`, значение — скопированный ключ.
   - Из терминала: `cd server && npx wrangler secret put SERPER_KEY` (значение
     вводится интерактивно, в файлы репозитория не попадает).

## Шаг 4. Первый деплой воркера

1. github.com → репозиторий **ai-platform** → вкладка **Actions** → в списке
   слева workflow **«Деплой воркера»** → кнопка **Run workflow**.
   (Начиная с этого момента можно и не запускать вручную: любой пуш с
   изменениями в папке `server/` сам запускает тот же workflow.)
2. Что делает job внутри: создаёт базу D1 `ai-platform-sync` (если её ещё
   нет), применяет миграции из `server/migrations`, деплоит воркер.
3. Если секреты из шага 2 ещё не заданы — job всё равно завершится зелёным, в
   логе будет пометка «Секреты Cloudflare не заданы — деплой пропущен»: это
   ожидаемо, не ошибка.

## Шаг 5. Включение синхронизации в приложении

Повторить на **обоих** устройствах (Мак и айфон):

1. **Настройки** → раздел **«Синхронизация»** → кнопка **«Настроить»**.
2. В поле **«Секретная фраза»** ввести одну и ту же длинную фразу на обоих
   устройствах — придумать её один раз и ввести везде одинаково. Из фразы
   локально выводятся идентификатор пространства и ключ шифрования; сама
   фраза никуда не отправляется и нигде не сохраняется.
3. Поле **«Адрес сервера»** уже предзаполнено адресом воркера по умолчанию —
   трогать не нужно.
4. Нажать **«Включить»**.
5. Проверить связь кнопкой **«Проверить связь»** — должен появиться тост
   «Сервер отвечает».

**Важно:** фраза не хранится и не восстанавливается. Одинаковая фраза на двух
устройствах объединяет их данные в одно пространство; любая другая фраза —
всегда новое, отдельное и пустое пространство (старые данные при этом на
сервере не удаляются, а просто перестают быть кому-либо видны — см.
docs/ROADMAP.md, пункт про жёсткую привязку фразы).

## Как проверить, что всё работает

- В разделе «Синхронизация» статус меняется на «включена · синк ЧЧ:ММ» вскоре
  после нажатия «Включить».
- Изменения в чатах на одном устройстве появляются на другом в течение
  ~90 секунд фонового автосинка, либо почти сразу — синк также планируется
  сразу после каждого ответа ассистента и после правок в настройках.
- Если статус показывает «ошибка: …» — сервер недоступен или адрес не тот;
  перепроверить шаги 1–4.
